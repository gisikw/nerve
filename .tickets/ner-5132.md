# Screenshot pipeline: headless webview capture for visual review

## Why

Visual review is currently bottlenecked on Kevin pulling down and launching
the app. A screenshot pipeline would let Exo capture UI state after builds
and drop images into notes/attachments or ticket comments — reviewable from
phone without touching a terminal.

## Approach ideas

- Headless WebKitGTK via `wpe-launch` or `webkit2gtk` scripting
- Tauri has no built-in headless mode, but the Vite dev server serves the
  frontend standalone — could drive it with a headless browser against
  the fake backend (ner-5129) once that exists
- Alternatively: `wlr-screencopy` or `grim` if running in a headless
  Wayland compositor (sway/cage)
- Output to notes/attachments/ for Flatnotes visibility

## Dependencies

- Pairs well with ner-5129 (fake backend) — screenshots without a live
  Matrix connection require canned data
- Not blocked on it though — could screenshot the login page or use a
  test account

## Notes

**2026-02-17 17:09:28 UTC:** Screenshot pipeline ships. npx tsx screenshot.ts captures the UI via headless Chromium + fake backend. Supports scenes (login, busy, fresh), room selection, custom viewport. Outputs to notes/attachments/ by default for Flatnotes visibility.
